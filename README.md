# Medical RAG

Vietnamese medical Q&A over crawled YouMed articles. Hybrid retrieval (dense + BM25, fused with RRF in Qdrant), optional reranking, answers generated by an LLM through OpenRouter with numbered sources.

```
backend/medical_rag/   ingestion/ (chunking + ingest), encoders, store, retrieval, generation, llm, api
frontend/              Next.js chat UI (proxies /api to the backend)
backend/scripts/       validate_ingest.py (index acceptance check), eval_retrieval.py (dense vs sparse vs hybrid)
serve_model/           embed_server.py (local embedding server)
docs/superpowers/      design specs and implementation plans
data/, test_case/      crawled articles and evaluation questions (not in git)
```

## Setup

Run every command below from the **repo root**: `data/`, `test_case/` and `qdrant_data/` are resolved relative to the working directory.

```bash
pip install -e "backend[dev]"
cp .env.example .env        # then fill in OPENROUTER_API_KEY and HF_TOKEN
```

The embedding server has its own environment (needs PyTorch, install the build that matches your GPU from pytorch.org):

```bash
cd serve_model
python -m venv .venv && .venv/Scripts/activate      # Windows; use .venv/bin/activate elsewhere
pip install -r requirements.txt torch
```

## Run

1. Embedding server (`google/embeddinggemma-300m`, port 8001):
   ```bash
   cd serve_model && uvicorn embed_server:app --port 8001 --env-file ../.env
   ```
2. Ingest the articles once (add `--recreate` after changing the embedding model or chunking):
   ```bash
   python -m medical_rag.ingestion.ingest --embed-url http://localhost:8001
   ```
3. API on port 8000:
   ```bash
   uvicorn medical_rag.api:app --env-file .env --port 8000
   ```
4. Frontend, then open http://localhost:3000/:
   ```bash
   cd frontend && npm install && npm run dev        # production: npm run build && npm start
   ```

Qdrant runs in local mode and holds a file lock, so only one process can open `qdrant_data/`: stop the API before ingesting or evaluating.

## API

| Route | Description |
|---|---|
| `POST /api/chat` | `{"question": "..."}` (1-1000 chars) returns `{"answer", "sources": [{n, title, url, section_path, type, text, score}]}`. `score` is `null` without a reranker. Embed or LLM failures return 502. |
| `POST /api/retrieve` | `{"question": "...", "mode": "dense|sparse|hybrid", "k": 10}` returns ranked chunks with separate `retrieval_score` and `rerank_score` |
| `GET /api/health` | `{"status": "ok", "points": <chunks in the index>}` |

## Configuration

| Variable | Required | Default |
|---|---|---|
| `EMBED_URL` | yes | - |
| `OPENROUTER_API_KEY` | yes | - |
| `HF_TOKEN` | for the embedding server (gated model) | - |
| `QDRANT_PATH` | no | `qdrant_data` (must exist; the API refuses to create it) |
| `LLM_MODEL` | no | `google/gemini-2.5-flash` |
| `RERANK_URL` | no | unset: no reranking |
| `API_URL` | no (frontend, server side) | `http://localhost:8000` |

Reranking is optional. The only reranker server is the Kaggle notebook `serve_model/serve_qwen3_kaggle.ipynb`, which sits behind a temporary tunnel; when `RERANK_URL` is unset or the call fails, results keep the RRF order.

## Evaluate and test

```bash
python backend/scripts/validate_ingest.py                      # index acceptance check
python backend/scripts/eval_retrieval.py --per-type 50         # dense vs sparse vs hybrid on test_case/
cd backend && python -m pytest -q                              # offline test suite
```

`eval_retrieval.py` reports, per article type and overall, whether the right article and the chunk holding the reference context appear in the top k (`article@k`, `chunk@1`, `chunk@k`) and the chunk MRR.
